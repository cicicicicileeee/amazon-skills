# cici-amazon-brand-research

从品牌与目标站点出发，生成面向业务负责人的中文市场研究。必填仅 `brand`、`marketplace`；其他参数使用下述默认值。它是由智能体调用可用工具执行的工作流，不是绕开数据权限的独立爬虫。

## 输入与启动

接受“调研【品牌】在 Amazon.de 的经营情况”等自然语言。先确认品牌实体及目标国家；仅在重名、品牌关系、站点或权限确实影响结果时追问，不在每次运行重新做长篇需求访谈。

默认：近12个完整自然月逐月经营数据；类目 Top100 用最近一个完整月；无法回溯时用当前快照并标注日期。筛选销量最高的2—3款主力产品，每款自动选择3—5款同用途、相近价位及当地有销售证据的竞品。社媒抱怨优先目标国家近12个月内容。官网查目标国家，缺失时参考美国或全球官网并标注市场差异。品牌不一定属于消费电子，类目、竞品、法规均重新识别。

可选输入：统计周期、ASIN或官方卖家、品牌别名/子品牌边界、指定竞品、预算、输出格式、已有数据包、门店或全球官网深挖。用户明确修改的参数优先。不默认遍历所有国家、全国门店或私有账号。

以用户时区确定研究日及完整月份。用标准库脚本初始化目录与日期：

```bash
python3 scripts/research_data.py init --brand "Example Brand" --marketplace "Amazon.de" --as-of "YYYY-MM-DD" --out "research-run"
```

路径相对本技能目录；实际执行时解析技能安装路径，输出写入当次工作区，不能写入已安装技能目录。日期用本次真实研究日替换。脚本生成 `run_config.json`、数据表表头和目录，不会自动获得远程数据。

## 执行流程

1. **确定口径与工具能力。** 读 [研究流程](references/research-protocol.md) 和 [数据字典](references/data-dictionary.md)。发现本次可用的 Sorftime MCP、网页/浏览器和用户授权数据。核对站点、历史范围、分页与变体计量方式，记录来源和覆盖缺口。
2. **先保留证据，再做分析。** 多路径发现目标品牌产品，排除同名品牌及“适用于该品牌”的第三方配件，保留排除原因。按月取数，区分子ASIN、父变体组、型号与SKU。不能以当前畅销列表冒充历史全量。
3. **品牌与类目。** 分析销量、销售额、匹配口径ASP、可核验在售数、价格及促销、产品组合和渠道。明确官方、授权经销商、Amazon零售、其他第三方与未知。对品牌涉及的真实叶子类目逐个分析 Top100，保留NodeID、中英文名称及母类目；不能把Top100份额写成全市场份额。
4. **主力与竞品。** 依据同一统计期排名选2—3款重点型号，说明销量依据和变体归并。每款选择3—5款直接竞品；标杆品牌单列。比较需求场景、规格与卖点、价格权益、评价痛点、Listing/A+、关键词与自然/广告位置、当地官网和站外宣传。广告曝光不能推断花费、ACOS或效率。
5. **官网与消费者抱怨。** 读 [抱怨采集与编码](references/social-complaints.md)。核验当地官网目录、配置、购买入口、当前可售状态与价格权益；采集社媒/论坛负面体验，Amazon低星评价独立统计。优先产品质量及使用体验，同时覆盖价格、交付、售后和渠道问题。
6. **当地经营条件。** 根据实际品类和国家查官方法规与平台要求，记录截至日期、适用主体、必要材料和经营影响。法规实时核验，不套用电子产品或欧盟清单。只有用户选择深挖时才统计门店，按直营、体验店、授权商及零售连锁分别定义。
7. **产出与复核。** 按 [报告规范](references/report-and-improvement.md) 使用 [报告模板](assets/report-template.md)。每条重要结论可追溯到数据与来源，区分事实、估算、推断和待验证假设。先给摘要，再给分析、行动建议、需确认事项和数据口径。输出格式遵循当次要求；未指定时交付Markdown报告、规范化CSV/JSON及证据索引，具备文档/表格能力时可生成Word或Excel；不要虚报未生成的文件。
8. **提出技能优化计划。** 每次运行都附 [优化提案](assets/skill-improvement-template.md)，可以写“本次没有足够依据建议修改”。未经用户批准，不修改本技能、默认值、提示词、脚本或GitHub内容。

## 计量与证据底线

- 没有可靠的完整抽样框时，写“已发现/可观测/已核验产品及覆盖范围”，不承诺所有在售商品。正价格、品牌店标识或购买按钮都不能单独证明品牌身份、官方卖家或现货。
- 缺失值不是0。第三方平台估算不是后台实销；不同估算源、实际销售和时间口径分别统计。报价、划线价、真实日常观察价、促销价及ASP分别存储。
- 父级销量不复制累加到每个子ASIN。无卖家分销量时，Buy Box名称只用于卖家快照，不能把整月销量分配给该卖家。
- 部分收入缺失时，同时披露覆盖销量和收入覆盖率；ASP用收入与销量均可用的匹配样本，不除以未覆盖销量。少于24个月不能计算两段完整12个月同比。
- 官网/社媒仅有公共信息就只分析公共信息。搜索摘要是发现线索，未读原文的内容不能升级为验证事实；受限平台记录缺口后继续其他可用来源。
- 社媒负面采样的主题占比只描述样本，不是品牌投诉率、缺陷率或国家总体口碑。不能仅凭语言判断消费者国家。

## 可复用处理与检查

按数据字典将远程结果映射成标准CSV，保留原始响应及来源索引，不在这里固定任何品牌官网API或MCP的参数版本。

```bash
python3 scripts/research_data.py aggregate --input research-run/data/asin_monthly.csv --out research-run/data/monthly_summary.csv
python3 scripts/research_data.py complaints --input research-run/data/complaints.csv --out-dir research-run/data/complaint_analysis
python3 scripts/research_data.py validate --run research-run
python3 scripts/test_research_data.py
```

`validate`检查标准文件、唯一键、时间与来源关联；它不证明全量覆盖、商业结论正确或已实时联网。工具受限时交付已核验部分和缺口说明，不静默换算或补造销量、价格、卖家身份、评论或门店数。可复制的独立提示词在 [PROMPT.md](PROMPT.md)。
